# にゅりカラーパレット工房

PixAI の画像生成モデル「Tsubaki.3」で使うカスタムカラーパレットを、色を見ながら設計するための Web アプリです。
HEX コードを知らなくても、色を触って・並べて・比べて配色を作り、HEX と比率を PixAI へ持っていけます。

- 無料・ログイン不要・広告なし・外部トラッキングなし
- バックエンドなし。すべて端末のブラウザ内で処理（外部送信なし）
- iPhone Safari を最優先に設計（PC・タブレットでも動作）

> **PixAI の非公式補助ツールです。** PixAI 運営とは関係ありません。
> PixAI への自動入力・アカウント連携・画像生成 API の呼び出しは行いません。

## できること

| 分類 | 内容 |
|---|---|
| 3系統 | Overall（全体）／Character（人物）／Background（背景）を独立して編集。系統ごとに「出力に含める」を切替（初期は Overall のみ） |
| 色選び | 彩度×明るさの色エリア、色相・彩度・明るさスライダー、HEX 直接入力（`#` なし・3桁・全角も可）、端末標準のカラーピッカー。すべて双方向に同期 |
| 色数と比率 | 1〜10色。比率は整数％で、どの操作のあとも合計100％・各1％以上を自動で維持 |
| 比率の調整 | スライダー、数値入力、±1ボタン、プレビューバーの境界ドラッグ（隣り合う2色だけが動く）、均等化 |
| 並び | 左右移動、反転、シャッフル（色と比率の組はそのまま、順番だけ変わる） |
| 固定 | 色ごとに「色を固定」「比率を固定」を別々に設定 |
| 配色の提案 | 選択色を基準にした調和6種（モノクロマティック／アナロガス／コンプリメンタリー／スプリット／トライアド／テトラード）と、全体の変化6種（明るめ・暗め・高彩度・低彩度・暖色寄り・寒色寄り）。候補を見てから採用、いつでも元に戻せる |
| 見え方の確認 | ブロック／グラデーション／ポスター風／人物×背景／3系統の並置 |
| 履歴 | 元に戻す・やり直す |
| 保存 | 端末内に複数保存（読込・名前変更・複製・削除・JSON 出力）。編集途中の状態も自動で保持 |
| 出力 | 転記チェックリスト、HEX＋比率のコピー、HEX だけコピー、HEX配色プロンプト（PixAI・NovelAI のプロンプト本文用。HEXのみ／ラベル付き2方式）、PNG 画像、JSON |
| プリセット | オリジナル32種（PixAI 公式のプリセットではありません）。オリジナル12／クラシカル3／低彩度3／高彩度3／情景3／ダークファンタジー8 の分類フィルター付き |

## 使い方

1. 上のタブで編集する系統（Overall / Character / Background）を選ぶ。PixAI に入れたい系統は「出力に含める」をオンにする。
2. 色のチップ（またはプレビューバーの色）をタップして選び、色エリアやスライダーで色を探す。
3. 比率をスライダー・数値・バーの境界ドラッグで整える。
4. 迷ったら「配色の提案を見る」で候補を眺めて採用する。変えたくない色は先に「色を固定」。
5. 右上の「保存」で端末に保存する。

## PixAI への転記方法

PixAI へは **手で入力** します（このアプリから直接は送れません）。

1. 「PixAIへ持っていく」→「転記チェックリスト」を開く。
2. 色の行をタップすると HEX コードがコピーされ、「済」の印が付く。
3. PixAI のカラーパレット編集画面で該当の系統を開き、HEX を貼り付けて比率を入力する。
4. アプリに戻って次の色へ。これを色数ぶん繰り返す。

まとめて控えたいときは「HEXと比率をコピー」で次の形式のテキストが得られます。

```
Overall
#F3E7E0 60%
#A9B4C6 40%

Character
#F6E3D7 30%
…
```

## HEX配色プロンプト（PixAI・NovelAI）

プロンプト本文に HEX コードを並べて、配色を誘導するための出力です。PixAI の公式カラーパレット機能を使わない、簡易的な方法として使えます。
「PixAI・NovelAIへ持っていく」→「HEX配色プロンプト」を開き、3つの出力方式から選びます。選んだ方式は次回も保持されます。

**① HEXのみ**（色の割り当てはAI任せ）— 全体／キャラクター／背景から1系統を選んで出力

```
#CC7F93, #533147, #142B29, #70A996
```

**② 人物＋背景**（ラベル付き）— Character と Background をまとめて出力。Overall は含めない

```
character palette: #CC7F93, #533147
background palette: #142B29, #70A996
```

**③ 全体＋人物＋背景**（ラベル付き）— 3系統をまとめて出力

```
overall color scheme: #F3E7E0, #A9B4C6
character palette: #CC7F93, #533147
background palette: #142B29, #70A996
```

出力のルール

- HEX はパレットの登録順のまま。比率は含めない（比率は公式カラーパレットに入力するための編集情報として扱う）。
- ラベル付き方式は系統ごとに改行する。空の行・ラベルだけの行・余分なカンマは出さない。
- 「出力しない」設定の系統は出力しない。②③では該当する行に「出力に含める」ボタンが出て、その場で有効にできる（「元に戻す」で戻せる）。一部の系統だけを出力しているときは、その旨を表示する。
- 出力する内容がないときはコピーできず、理由を表示する。
- 配色帯は、出力する内容に合わせて系統ごとに均等幅で表示する。

注意

- HEX の羅列やラベル付き HEX は、配色を誘導する**実験的なプロンプト方式**です。PixAI・NovelAI とも、色の厳密な再現や、人物・背景など部位ごとの塗り分けは保証されません。
- どの方式が良いかは、モデル・プロンプト・seed によって変わりえます。現時点では同 seed での予備的な比較の段階で、特定の方式が常に優れるとは言えません。

## カラーパレットの挙動に関する注意

- 比率は生成画像のピクセル面積を厳密に指定する値ではなく、**色の存在感を誘導する目安**です。
- 同じパレットでも、プロンプト・seed・その他の設定で結果は変わります。
- アプリ内のプレビューは一般的な配色確認用の表示です。Tsubaki.3 が生成するイラストの予測でも、PixAI の内部処理の再現でもありません。
- 配色の提案は色彩理論に基づく機械的な候補で、仕上がりの良し悪しを保証しません。
- 色数の上限（10色）と3系統の区分は、開発時の仕様書に記載された Tsubaki.3 の仕様に合わせています。PixAI 側の仕様が変わった場合は `js/config.js` の定数を修正してください。

## プリセットの追加方法

`js/presets.js` の `PRESETS` に1行足すだけで追加できます。

```js
{ cat: 'darkfantasy', name: '名前', desc: '短い説明。', colors: [['#24090E', 30], ['#650E23', 25], ['#B51E35', 20], ['#E35A66', 15], ['#E9C1B1', 10]] },
```

- `cat` は `PRESET_CATEGORIES` の `key`。分類を増やすときは `PRESET_CATEGORIES` に1行足します（並び順がそのまま画面の表示順になります）。
- 1〜10色、比率は整数で合計100、各1％以上。名前・配色の重複は不可。HEX は `#RRGGBB`（大文字）。
- これらは `npm test` で自動的に検証されます。
- ダークファンタジー8種の比率は、暫定で 30/25/20/15/10 にしています。

## データの保存とバックアップ

- 「保存」したパレットと編集中の状態は、ブラウザの localStorage（この端末・このブラウザの中）に入ります。
- **ブラウザのデータ削除、プライベートブラウズ、端末やブラウザの変更で失われます。** iOS の Safari は、長期間開かなかったサイトのデータを自動で消すことがあります。
- 残したいパレットは **JSON で保存**してください。「PixAIへ持っていく」→「JSONで保存」→「ファイルで保存」（または「テキストをコピー」してメモアプリ等へ）。
- 復元は「JSONを読み込む」から。ファイルを選ぶか、テキストを貼り付けます。
- JSON は **このアプリ独自の形式**です。PixAI にインポートできる公式形式ではありません。
- PNG は見返す・共有するための画像で、アプリに読み込み直すことはできません。

### JSON の形（schemaVersion 1）

```json
{
  "schemaVersion": 1,
  "app": "nyuri-color-palette-workshop",
  "id": "p_xxxxxxxx",
  "name": "薄紅の肖像",
  "createdAt": "2026-11-13T00:00:00.000Z",
  "updatedAt": "2026-11-13T00:00:00.000Z",
  "scopes": {
    "overall":    { "enabled": true,  "colors": [ { "id": "c_xxxx", "hex": "#F3E7E0", "ratio": 60, "lockColor": false, "lockRatio": false } ] },
    "character":  { "enabled": false, "colors": [ ] },
    "background": { "enabled": false, "colors": [ ] }
  },
  "memo": ""
}
```

読込時には構造・色数・HEX・比率・スキーマバージョンを検証し、不正なデータは読み込まずにエラーを表示します。
有効な系統は「1色以上・整数・各1％以上・合計100％」が必須です。

## ファイル構成

```
index.html            画面の骨組み
css/style.css         見た目（モバイル優先）
js/config.js          定数（色数上限・系統の定義など）
js/color.js           色変換（HEX / RGB / HSV / HSL）
js/ratio.js           比率計算（最大剰余法・合計100％の保証）
js/harmony.js         色彩調和・バリエーション
js/palette.js         データ構造・JSON 検証・スキーマ移行の受け皿
js/presets.js         オリジナルプリセット（分類 PRESET_CATEGORIES と一覧 PRESETS。1行足せば追加できる）
js/storage.js         端末内保存
js/exporter.js        テキスト・PNG 出力
js/picker.js          タッチ対応のスライダー／色エリア
js/app.js             画面の描画と操作
tests/logic.test.js   自動テスト（色変換・比率・調和・JSON 検証・保存）
tests/browser/ui_test.py  ブラウザ操作テスト
```

フレームワーク・外部ライブラリ・ビルド工程はありません。

## 開発・ローカル起動

ES Modules を使っているため、`index.html` をファイルとして直接開いても動きません。簡易サーバーを立ててください。

```bash
python3 -m http.server 8000
# → http://localhost:8000 を開く
```

## テスト

```bash
# ロジックの自動テスト（Node.js 20 以上。追加インストール不要）
npm test

# ブラウザ操作テスト（Python + Playwright + Chrome）
pip install playwright
python3 tests/browser/ui_test.py
```

ブラウザ操作テストは Chrome を iPhone 相当の画面サイズ・タッチ有効で動かすものです。
**iPhone 実機の Safari での確認は別途必要です**（描画エンジンが異なります）。

## GitHub Pages で公開する

1. GitHub で新しいリポジトリを作る（例：`nyuri-color-palette-workshop`）。
2. このフォルダの中身をすべて、リポジトリの直下に置いて `main` ブランチへ push する（`index.html` が一番上に来るように）。
3. リポジトリの **Settings → Pages** を開く。
4. **Source** を「Deploy from a branch」、**Branch** を `main`／`/(root)` にして Save。
5. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

ビルド不要なので GitHub Actions の設定は要りません。`.nojekyll` は Jekyll 処理を省くための空ファイルです。
